## 조작 (3D 코트)
WASD 이동 · 마우스 좌우 방향 · Q 올리기 / E 찍기 / 좌클릭 직선 (꾹 = 충전, 떼면 스윙) · Space 점프 · Shift 팔 뻗기
T 꾹 = 감정표현 원판 · G 셔틀 그림자 · L 낙하 표시 · M 소리
서브: Q 꾹 (짧게 숏 서브, 길게 롱 서브) · 셔틀이 라켓 팔 어깨 근처로 오면 슬로우

## 조작 (클래식)
←→ 이동 · ↑ 점프 · ↓ 앉기 · A 대쉬(Shift도 됨) · Q 클리어 · W 드라이브 · E 드롭 · R 헤어핀 · Space 스매시
(왼손: 새끼 Q · 약지 W · 중지 E · 검지 R · 엄지 Space · 새끼 한 칸 아래 A)
서브: Space 길게(길수록 멀리, 너무 짧으면 네트·너무 길면 아웃) · Esc 메뉴

## 조작 (모바일 · 터치 버튼)
터치 기기에서 열면 자동으로 켜짐 (PC에서 확인하려면 주소 끝에 `?touch`). 가로 화면 추천 — 왼쪽 이동 패드 · 가운데 코트 · 오른쪽 버튼, 세로면 코트 아래에 버튼.
- 클래식: 패드 ◀▶ 이동 · ▲ 점프(위로 미는 순간) · ▼ 앉기 / 오른쪽 클리어·드라이브·드롭·헤어핀·스매시(꾹 = 서브 게이지) · ⚡ 대쉬(패드로 이동 중에)
- 3D: 패드 8방향 이동 / 방향 ◀ ● ▶ (상대 코트 왼쪽·가운데·오른쪽, 서브도 이 방향) · 올리기(서브)·찍기·직선 꾹 → 떼면 스윙 · 점프 · 런지 · 😀 꾹 → 밀어서 감정표현
- 버튼은 누르는 순간 실행(pointerdown), 이동과 샷을 두 엄지로 동시에 가능(멀티터치)

## 새 게임 종류 추가 방법
1. js/<게임id>/ 폴더에 게임 코드 작성, index.html에 화면(div)과 script 추가
2. app/catalog.js의 GAME_TYPES에 등록 (modes에 지원 모드)
3. app/main.js의 screens와 launch()에 연결

- ES 모듈(`type="module"`)은 더블클릭(file://) 실행에서 막히므로 일반 `<script src>` 사용.
- index.html의 script 순서 중요 (Athlete가 Player/AIOpponent보다 먼저).

## 계정 (Supabase)
- 로그인 없이도 플레이 가능(게스트). 기록은 항상 이 브라우저(localStorage)에 먼저 저장.
- 로그인하면 AI 대전 결과가 matches 테이블에 올라감. 실패한 기록은 대기열에 두었다가 다시 올림.
- 훈련 레벨은 로그인 시 progress 테이블과 합침(종목별 높은 값).
- 테이블: profiles(닉네임) · matches(경기 기록) · progress(훈련 레벨), 모두 RLS로 본인 것만 쓰기.
- account.js의 키는 publishable(공개용). secret/service_role 키는 절대 넣지 말 것.

## 친선게임 (클래식, 온라인)
- 대기화면 → 레트로 모드 → 친선게임. 닉네임을 적고 방 만들기/입장 (3D 방과 채널이 달라서 둘 다 클래식을 골라야 함).
- 채널 `bmc-<코드>`: 각자 내 선수 상태를 초당 20번 보냄 · 칠 때는 셔틀 출발점·도착점·비행시간만 보냄(클래식 궤적은 이 세 값으로 결정)
  · 받는 쪽 컴퓨터가 낙하/네트를 판정해 'pt'로 점수를 알림 · 내 화면에선 항상 내가 오른쪽(상대 x는 W − x로 뒤집음).
- 첫 서브·목표 점수는 방장 기준. 상대가 나가면 경기 중단, 같은 코드로 다시 들어오면 새 경기(세트 스코어는 유지). 기록은 이 브라우저에만.

## 닉네임 (친선게임 공용)
- 대기화면 친선게임 설정의 닉네임 칸. 비어 있으면 입장 불가. 입력할 때마다 localStorage `badminton.nick`에 저장되어
  메뉴로 돌아오거나, 다른 판·새로고침 후에도 그대로 채워져 있음. 처음엔 로그인 닉네임으로 채움.

## 친선게임 (3D 코트, 온라인)
- 대기화면 → 3D 코트 → 친선게임 → 한 명이 '방 만들기'(5자리 코드), 친구는 코드 입력 후 '입장'. 인터넷 필요, 로그인 불필요.
- 별도 서버 없이 Supabase Realtime 채널 `bm3d-<코드>`의 broadcast·presence만 사용 (DB 테이블 안 씀).
- 동기화: 각자 자기 선수 위치를 초당 15번 보냄 · 칠 때는 발사 위치·속도만 보냄(셔틀 물리는 결정론적이라 양쪽 궤적 동일)
  · 판정(타격/낙하/득점)은 셔틀을 받는 쪽 컴퓨터가 결정해 알림 · 좌표는 받는 쪽에서 180° 회전(x→−x, z→−z).
- 첫 서브·목표 점수는 방장 기준. 온라인 경기는 서버(matches)에는 저장하지 않고 이 브라우저 기록에만 남김(내 기록 → 친선게임).
- 상대가 나가면 'pause'(서브 불가), 남은 쪽이 방장이 됨. 같은 브라우저(localStorage badminton.cid)가 같은 코드로 다시 들어오면
  남은 쪽이 점수·서브·세트·엔드를 'resume'으로 보내 이어서 진행(중단된 랠리는 무효).
- 같은 상대와 계속하면 세트 스코어 유지(점수판 아래). 15점 이상 경기는 절반 점수에서 코트 체인지, 경기마다 엔드 교대.
- Supabase 대시보드에서 Realtime을 '비공개 채널만 허용'으로 바꾸면 방이 연결되지 않음.

## 재화 (코인) — 3D 코트 전용, 수치는 모두 [게임]
- 플레이로만 얻음. 끝까지 한 경기만 지급(중간에 나가면 없음). 레트로 모드·훈련(레벨업 제외)·튜토리얼은 지급 없음.
- AI 대전 승리(11점 기준): 쉬움 20 · 중간 35 · 어려움 55 · 지옥 80 · 임파서블 110 / 목표 점수 15점 ×1.3 · 21점 ×1.7
- 패배: 승리 보상 × 0.4 × (내 점수 ÷ 목표 점수) — 0점으로 지면 0 (일부러 빨리 지는 것 방지)
- 오늘의 첫 승 +50 (한국 시간 하루 1번) · 긴 랠리(그 경기 최장) 10타 +5 / 20타 +15 / 30타 +30
- 커리어: 처음 깨는 경기 ×2 · 이미 깬 경기 다시 하기 ×0.5 · 대회 첫 우승 +100 / 150 / 250 / 400
- 일일 챌린지: 그날 첫 도전 +20 · 그날 최고 점수 25점당 1 (만점 110, 최고 점수가 오른 만큼만)
- 훈련 레벨업 +30 · 친선게임 승 15 / 패 10 (하루 5경기까지)
- 저장: 브라우저 `badminton.wallet.v1`. 로그인하면 wallets 표와 합침 — 서버 값 + 아직 안 올린 변화량(delta). 게스트로 번 코인은 첫 로그인 때 계정에 더해짐.
- 대기화면 계정 줄의 🪙 버튼 = 잔액·얻는 방법·최근 내역. 쓰는 곳은 `Wallet.spend(이름, 금액)`으로 붙임(채·스킨).

## 채 시스템 — 3D 코트, AI 대전·커리어에만 적용
- [실제 참고] 헤드가 무거운 채 = 스매시에 힘이 실리지만 다루기 느림 / 헤드가 가벼운 채 = 빠르게 다뤄 수비·네트에 유리. [게임] 수치·가격은 모두 게임용.
- 균형형: 기본(무료), 효과 없음. 헤드 헤비·헤드 라이트: 각 300코인. 강화 +1/+2/+3 = 200 / 350 / 500코인 (채 하나를 끝까지 = 1,350코인).
- 강화할수록 장점과 단점이 함께 커짐. 산 단계 안에서 −/＋로 낮춰 쓸 수 있음(쓰는 단계 = `Gear3.use`).

| 강화 | 헤드 헤비 ＋ | 헤드 헤비 － | 헤드 라이트 ＋ | 헤드 라이트 － |
|---|---|---|---|---|
| +0 | 스매시 각 −1.0° · 상대 반응 +15ms | 충전 시간 +10% · 정타 여유 −6% | 충전 시간 −10% · 정타 여유 +10% | 스매시 각 +1.0° |
| +1 | −1.5° · +25ms | +15% · −9% | −15% · +15% | +1.5° |
| +2 | −2.0° · +35ms | +20% · −12% | −20% · +20% | +2.0° |
| +3 | −2.5° · +45ms | +25% · −15% | −25% · +25% | +2.5° |

- 스매시 각은 근력 훈련 효과(레벨당 −1.5°)와 더해짐. 시험값(충전 90%, 높이 2.6m, 뒤쪽 4.5m): 0° 약 165km/h · −2.5° 약 198km/h · +2.5° 약 147km/h.
- 친선게임·일일 챌린지·훈련·튜토리얼은 채 효과 없음(모두 같은 조건). 경기 화면 '설정' 칸에 장착한 채 표시.
- 저장: 브라우저 `badminton.gear.v1` · 로그인하면 wallets 표의 gear 칸과 합침(채마다 더 높은 강화 단계).

## 선수 스탯 — 3D 코트, AI 대전·커리어에만 적용 (수치는 모두 [게임])

## 빠른 대전 — 자동 매칭 (3D 코트, court3d/quick.js)
- 대기화면 → 빠른 대전 → 시작. 11점 경기, 채·선수 스탯 효과 없이 같은 조건(체력은 켜짐, 스킨은 보임). 연결은 친선게임과 같은 방식(방 코드는 자동).
- 매칭 점수(Rate3) [게임]: 처음 1000 + 20 × 선수 레벨, 그 뒤로는 빠른 대전 승패로만 변함(엘로 방식 K = 32). '비슷한 스탯' = 이 점수. 같으면 선수 레벨이 가까운 쪽.
- 대기열(Quick3): Supabase Realtime 채널 `bm3d-queue`의 presence에 { 점수, 레벨, 이름, 대기 시작 시각 }. 허용 차이 처음 ±100, 3초마다 +50(둘 중 오래 기다린 쪽 기준).
  허용 범위 안에서 점수 차가 가장 작은 사람에게, 두 사람 중 id가 작은 쪽이 초대(inv) → 수락(ok)하면 둘 다 대기열을 나가 같은 방으로. 4초 안에 답이 없거나 거절(no)이면 6초간 건너뜀.
- 25초 동안 대기자가 한 명도 없으면 AI와 대전(매칭 점수 950 미만 쉬움 · 1100 미만 중간 · 1250 미만 어려움 · 그 이상 지옥). AI전은 매칭 점수에 반영 안 됨.
- 경기 끝: 결과 창에 매칭 점수 변화. 재대결(Enter)도 매번 반영. 상대가 중간에 나가면 지금은 점수 변화 없음(랭크전에서 서버 판정과 함께 처리 예정).
- 순위표: 로그인한 사람의 매칭 점수 상위 10명(sql/ratings.sql). 점수는 브라우저가 계산 — 조작 방지는 아직 없음.
- 저장: 브라우저 `badminton.rating.v1` · 로그인하면 wallets 표 gear 칸의 `_rate`(경기 수가 많은 쪽)와 ratings 표.

- 보호 방식: 비밀번호는 화면을 여는 장치일 뿐(코드가 공개되므로). 코드에는 값 대신 해시만 있음. 가입자·통계는 Supabase 함수 `dev_report`가 돌려주며,
  `admins` 표에 등록된 계정으로 로그인했을 때만 응답. 게스트·다른 계정은 「이 브라우저」 탭만 보임.
- 설치: Supabase SQL Editor에서 sql/dev.sql 실행(★ 줄에 내 이메일을 넣어 개발자 계정 등록). 비밀번호를 바꾸려면 dev.js의 HASH를 `Dev.hash('새 비밀번호')` 값으로 교체.
- [게임] 11번·간격·화면 구성은 모두 임의로 정한 것.

## 랭크전 — 서버가 점수를 관리 (court3d/rank.js · sql/ranked.sql, 4단계 17번)
- 대기화면 → 3D 코트 → 랭크전. 로그인 필수, 11점 경기, 채·선수 스탯 효과 없음, 사람과만(대기자가 없어도 AI로 넘어가지 않음). 재대결 없음 — 끝나면 메뉴에서 다시 상대를 찾음.
- 빠른 대전(매칭 점수는 각자 브라우저가 계산)은 그대로 두고, 랭크전은 별도 점수(ranks 표)를 씀. 대기 채널도 따로(`bm3d-rankq`).
- 설치: Supabase SQL Editor에서 sql/ranked.sql 한 번 실행. 실행 전에는 대기화면에 '준비 중'으로 나옴.
- 서버 쪽 규칙 (수치는 모두 [게임])
  - `ranks`·`rank_matches` 표는 게임에서 읽기만 가능. 점수는 함수(rank_open / rank_beat / rank_report)만 바꿈.
  - 경기는 두 사람이 서로를 상대로 지목(rank_open)해야 열림. 끝나면 각자 결과를 보고(rank_report)하고 **두 보고가 같을 때만** 반영.
  - 보고가 다르면 '분쟁': 점수 변화 없음, 두 사람의 분쟁 횟수 +1 (개발자 화면 유저 탭의 '랭크 분쟁'으로 확인).
  - 도중에 나가기(Esc) = 기권패. 창을 닫아 버린 경우: 남은 쪽이 '상대가 나감'으로 보고 → 상대 신호(10초마다 rank_beat)가 20초 넘게 없으면 몰수승.
  - 점수 미반영: 40초 안에 끝난 경기, 30초 안에 상대가 나간 경기, 둘 다 '상대가 나갔다'고 한 경기(연결 끊김), 같은 상대와 하루 3경기를 넘은 경기.
  - 점수: 엘로 방식, K = 32 고정, 최저 100. 이긴 만큼 상대가 잃으므로 경기 수만 늘려서는 오르지 않음(참가 점수·연승 보너스 없음).
  - 티어: 아이언 <750 · 브론즈 750 · 실버 900 · 골드 1050 · 플래티넘 1200 · 다이아 1350 · 마스터 1500. 순위표는 랭크전 3경기 이상.
  - **배치고사** (rank_place, 한 계정에 한 번): 랭크전을 처음 누르면 AI와 11점 5경기. 첫 상대는 중간, 이기면 다음은 한 단계 위·지면 한 단계 아래(쉬움~임파서블). 채·선수 스탯 효과 없음.
    시작 점수 = 5경기 평균 of (700 + 150 × AI 단계, 이기면 +100 / 지면 −100) → 전패 630(아이언) ~ 전승 1220(플래티넘). 예: 승승패승패 = 1050.
    진행은 브라우저(`badminton.place.v1`)에 저장되어 이어서 할 수 있음. 경기 도중 다시 시작 불가, 점수가 난 뒤 나가면 그 경기는 패배.
    배치고사는 브라우저에서 AI와 하는 경기라 서버가 진위를 확인할 수 없음 → 서버는 단계 순서·점수 형식만 검사하고 시작 점수를 1220까지로 제한. 다이아 이상은 사람과의 랭크전으로만.
- 판정 검증 (게임 쪽, Rank3.checkShot / checkPoint): 셔틀 물리가 양쪽에서 같게 계산되는 점을 이용해 상대가 보낸 타구·판정을 내 계산과 비교.
  - 이상으로 보는 것: 발사 속력 160m/s 초과 · 코트 밖 타점 · 내 타구 경로에서 2.6m 넘게 떨어진 타점 · 15cm 넘게 안쪽에 떨어진 내 공을 상대 득점으로 판정 · 자기가 친 공에 자기가 득점 판정.
  - 이상이 2번 이상이면 결과 보고에 실려 서버가 그 경기를 분쟁 처리.
- 한계 [확인된 사실]: 서버가 랠리 자체를 계산하지는 않음(별도 게임 서버 없음). 조작한 게임으로 **점수를 올릴 수는 없지만**, 일부러 다른 결과를 보고해 경기를 분쟁(무효)으로 만드는 것은 막지 못함 — 분쟁 횟수로 사람이 가려내야 함. 상대 선수 위치를 속이는 것(순간이동)도 검사하지 않음.
